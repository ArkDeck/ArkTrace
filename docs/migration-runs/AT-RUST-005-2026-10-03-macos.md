## 实现与证据范围

- `VerifiedExecutable` 只接受私有只读 arm64 Mach-O 快照；完整 SHA-256 与有效 code signature
  都需匹配。开发 pin 仍验签，不提供 skip-trust。生产策略要求限定 Developer ID Team/identifier
  和 hardened runtime；本次只验证生产策略拒绝开发样本，未取得生产签名正向证据。
- `posix_spawn` 使用 executable、literal argv、held CWD、固定四项 environment、独立进程组、
  空 signal mask 和明确 stdio。实际测试未继承 held FDs；系统可能额外加入当前 UID 的
  `__CF_USER_TEXT_ENCODING`，测试只允许其受限格式，不允许其它任意环境字段。
- helper 与 parser 均挂起启动，以 Security guest/kernel code identity 比较已验证 CDHash 后才恢复。
  Security FFI 按 Xcode 27 的声明核对；guest API 依据
  [Apple SecCodeCopyGuestWithAttributes](https://developer.apple.com/documentation/security/seccodecopyguestwithattributes(_:_:_:_:))。
  网络校验关闭；生产 notarization gate 另待完成，不能由本地静态验签代替。
- 专用 `arktrace-host-process` 负责生命周期监督，不承载 Trace/Store 语义。Engine 唯一 control
  writer 关闭后，helper 独立线程取消并向 parser 组发 TERM，最多 500 ms grace 后 KILL。
  清理期间保留未 reap leader，避免向复用 PID/group 发信号；孙进程即使关闭管道也检查 live group members。
- stdout/stderr 各受独立 64 KiB 上限约束。子进程写端保持 blocking；parent 非阻塞 drain。
  helper 协议有 128 KiB 请求、600,000 byte 响应上限与发送截止时间，明确处理部分写入和 EPIPE。
  helper 忽略 SIGPIPE，让错误路径执行 ownership guards；parser 恢复默认 signal 行为。
  取消返回前完成可观察清理；`CleanupFailed` 不被取消覆盖。机器错误没有 pathname/诊断 prose。

Darwin 对 zombie-only process group 的 TERM 返回 `EPERM`，本次已实际确认并处理：只有 bounded
native process inspection 证明组内无 live member 时才允许该结果；不能笼统忽略 EPERM。
直接 child 被 `waitpid` 回收；宿主死亡后 helper 与孙进程的存活检查通过，不声称其它未测窗口通过。

## 未完成项与下一步

helper 的初始挂起核验窗口尚无独立 watcher：Engine 此时死亡不能保证该 helper 自清理。
本次父死亡正向证明范围是 helper 已启动且 parser 子树运行时，不能扩展到启动全过程。
需补齐此窗口、全部取消/launch race 窗口、panic/cleanup-failure 注入与 owner/crash recovery 集成。
sidecar 目前只在 probe 结束后检查，尚无解析期间的实时字节预算。

`signedBundleInPlace`、sealed bundle 外层资源身份、沙箱、实际生产 Developer ID/hardened/notarization、
固定 supervisor 发布 pin 和发行布局，以及 Windows Job/DACL/handle inheritance 都尚未验收。
测试替身经 `process-fixtures` feature 隔离，发布构建不得启用；新 helper 还未被任何生产消费者选择。

下一步补进程监督启动与 staging/owner 故障窗口，再把同一端口接入 006 的 parser/schema/index/Ready
实现。CLI/SDK/App/ArkDeck 接入、medium/large 性能、最终切换与回滚仍是 active Goal 的必需工作。
